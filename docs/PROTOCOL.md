# XTunnel protocol

This document describes the XTunnel v1 wire protocol. The application protocol
negotiated over QUIC ALPN is `xtunnel/1`.

## Roles

Fixed for the whole session:

| Party | ICE role | QUIC role |
| --- | --- | --- |
| `share` (host) | controlling | client (dials) |
| `connect` (joiner) | controlled | server (listens) |

## Identity and authentication

Each peer generates an ephemeral self-signed ECDSA P-256 certificate per
connection attempt. Authentication pins the SHA-256 fingerprint of the peer's
leaf certificate; the chain is never trusted (QUIC runs with
`InsecureSkipVerify` plus a `VerifyPeerCertificate` that compares the leaf
digest to the expected fingerprint). Both directions are pinned.

Fingerprints travel inside the PAKE-encrypted `hello` frame (signaled pairing)
or inside the pairing blob (offline pairing, where the copy-paste channel is the
trust anchor).

## Pairing codes

A code is `<nameplate>-<secret>`, for example `47-905183`.

- The **nameplate** (1 to 5 digits) is assigned by the signaling server and only
  routes the two peers into the same room.
- The **secret** is 6 digits generated by `share` with a CSPRNG. It never reaches
  the server.

The PAKE password is the whole code, so a server that knows only the nameplate
cannot derive the session key or man-in-the-middle the pairing.

## Signaling mailbox

Peers reach the server over a WebSocket at `/ws`. The operation is carried in the
query string so a router (the Cloudflare relay) can send the upgrade to the right
room before any message is read:

```
wss://<server>/ws?op=create
wss://<server>/ws?op=join&room=<nameplate>
```

Messages are JSON envelopes:

```
client -> server:  {type: "create"}
                   {type: "join", room}
                   {type: "msg", body}
server -> client:  {type: "created", room, turn?, reconnect?}
                   {type: "joined", turn?, reconnect?}
                   {type: "peer"}              sent to the host when the joiner arrives
                   {type: "msg", body}         the other peer's opaque payload
                   {type: "peer-left"}
                   {type: "error", error}
```

`body` is base64 in JSON and opaque to the server. `turn` carries ephemeral TURN
credentials when the server runs a relay. `reconnect: true` means the room stays
open after pairing, so the peers may run further connection rounds over it.

The Cloudflare relay refuses bad joins before upgrading, with the status and
text below. `xtunneld` upgrades first and answers with an `error` envelope
carrying the same text.

| Status | Body | Meaning |
| --- | --- | --- |
| 400 | `invalid room` | malformed nameplate |
| 404 | `no such room (codes are one-time and expire)` | unknown or expired room |
| 409 | `room is full` | the room already has a joiner |
| 429 | `rate limited` | too many requests from this address |

### Servers

| | Cloudflare relay | `xtunneld` |
| --- | --- | --- |
| Nameplates | random, 1 to 3 digits, 5 when busy | same |
| Unpaired room lifetime | 10 minutes | 10 minutes |
| Paired room lifetime | 5 minutes | 24 hours |
| Messages per peer | 16, at most 32 KiB each | unlimited, 1 MiB each |
| `reconnect` | no | yes |
| TURN credentials | no | optional |
| Rate limit | per IP, per Cloudflare location | per IP |

## PAKE and encrypted frames

Both peers run SPAKE2 over P-256 (`schollz/pake` v3) with the transcript
`xtunnel/1|<code>`. The host sends the first PAKE message. The shared secret is
expanded with HKDF-SHA256 into two ChaCha20-Poly1305 keys:

```
hostKey = HKDF-SHA256(K, info="xtunnel/sig/host->join")
joinKey = HKDF-SHA256(K, info="xtunnel/sig/join->host")
```

Every following `msg` body is an AEAD frame:

```
[8B counter, big endian] || AEAD_seal(key, nonce=counter, plaintext, aad=counter)
```

The counter must increase strictly by one. The plaintext is
`{"t": type, "d": payload}`. A frame that fails to decrypt means the peers hold
different keys, that is, a wrong or guessed code, and pairing aborts. A
malicious server therefore gets one online guess per code.

## Connection rounds

Each round is a two-message exchange of `hello` frames carrying everything
needed for one connection attempt (non-trickle ICE):

```
hello = {fp, ufrag, pwd, cands: [ICE candidate strings], rid, reply}
```

The joiner opens with a fresh random `rid`; the host answers with the same
`rid` and `reply=true`. Both sides drop buffered frames at the start of a round
and ignore hellos from other rounds. Then both add the remote candidates, run
ICE (host dials, joiner accepts) and perform the QUIC handshake.

When the server set `reconnect`, the peers keep the mailbox open and run a new
round over the same encrypted channel whenever the tunnel drops. Otherwise they
close the mailbox once the tunnel is up.

## Offline pairing blob

Printable form: `xt1_` + base64url(raw), no padding. Raw layout:

```
[1B  version<<4 | flags]      flags bit0: 1 = answer blob
[16B seed]                    ICE ufrag/pwd derived from this
[32B cert SHA-256 fingerprint]
[1B  candidate count]         (<= 8)
repeated candidate:
  [1B  flags]                 bit0: 1 = IPv6
  [4B or 16B IP]
  [2B port, big endian]
```

ICE credentials are derived from the seed:

```
ufrag = base64std( HKDF-SHA256(seed, info="xtunnel/ice-ufrag", 12 bytes) )
pwd   = base64std( HKDF-SHA256(seed, info="xtunnel/ice-pwd",   18 bytes) )
```

## Data plane (over QUIC)

- One QUIC connection per pairing.
- The host opens one control stream and sends the port registry:

  ```
  [1B type=0x01 registry][2B count][2B port]...
  ```

- The joiner opens one bidirectional stream per forwarded TCP connection:

  ```
  [1B protocol version][2B target port]
  ```

  The host answers with one status byte (`0x00` OK, `0x01` port not shared,
  `0x02` local dial failed), then raw bytes flow both ways.

- TCP half-close maps to QUIC stream FIN; abnormal teardown maps to
  `CancelRead`/`CancelWrite`. Closing the tunnel on purpose uses application
  error code 0, which the other side reports as "closed by the other side".

## Relay fallback (`xtunneld`)

The embedded TURN server (pion/turn) issues time-windowed credentials
(RFC 8489 long-term style): username = expiry unix timestamp, password =
base64(HMAC-SHA1(username, shared secret)). Peers add the relay as an ICE
server; if hole punching fails, ICE nominates a relay candidate pair. QUIC/TLS
terminates only at the peers. `InitialPacketSize` is capped at 1150 bytes and
PMTUD is disabled to stay within TURN framing overhead.
